# 文件管理模块重构方案

## 一、目标

将当前零散的文件上传/下载能力升级为**三端统一、业务可追溯、具备预览能力**的文件管理体系。

---

## 二、数据库变更

### file 表新增字段

```sql
ALTER TABLE `file`
    ADD COLUMN `biz_type`  VARCHAR(30)  DEFAULT NULL COMMENT '业务类型' AFTER `file_type`,
    ADD COLUMN `biz_id`    INT UNSIGNED DEFAULT NULL COMMENT '业务记录ID' AFTER `biz_type`,
    ADD COLUMN `file_size` BIGINT       DEFAULT NULL COMMENT '文件大小（字节）' AFTER `file_path`,
    ADD COLUMN `mime_type` VARCHAR(100) DEFAULT NULL COMMENT 'MIME类型' AFTER `file_size`;

ALTER TABLE `file`
    ADD INDEX `idx_biz` (`biz_type`, `biz_id`);
```

### 字段说明

| 字段 | 用途 |
|------|------|
| `biz_type` | 文件归属的业务领域，见下方业务类型表 |
| `biz_id` | 对应业务记录的 ID（如报名记录 ID、场次 ID） |
| `file_size` | 文件大小，前端展示用 |
| `mime_type` | 如 `image/jpeg`、`application/pdf`，预览时决定 Content-Type |

### 业务类型定义

| biz_type | 对应业务 | biz_id 含义 | 可见范围 | 来源方式 |
|----------|---------|-------------|---------|---------|
| `user_profile` | 用户资料（身份证、头像等） | user_id | 本人、管理员 | 用户上传 |
| `enrollment` | 学员报名材料 | user_id | 本人、管理员 | 用户上传 |
| `registration_form` | 报名表 PDF | user_id | 本人、管理员 | 系统生成 |
| `exam_ticket` | 准考证 PDF | exam_registration_id | 本人、管理员 | 系统生成 |
| `training_record` | 培训记录表 PDF | user_id | 本人、管理员 | 学员触发生成 |
| `physical_exam` | 体检报告 | user_id | 本人、管理员 | 学员上传 / 组员接口 |
| `license_upgrade` | 增驾/准教车型变更材料 | coach_vehicle_app_id | 本人、管理员 | 用户上传 |
| `coach_qualification` | 教练资质材料 | user_id | 本人、管理员 | 教练上传 |

> 注：教练不可查看学员的任何文件。

## 四、接口设计（方案 A：统一 FileController + 角色权限）

### 4.1 上传文件

```
POST /files/upload

Params: file (Multipart), bizType, bizId (可选)
权限:  登录用户
逻辑:  - 强制校验当前用户只能上传自己的文件（管理员例外）
       - 自动采集 fileSize / mimeType / 扩展名校验
       - 关联 bizType + bizId
```

### 4.2 下载文件（含预览）

```
GET /files/{id}/download?preview=false

权限:  文件所有者 / 管理员
逻辑:  - preview=false → 附件下载（attachment）
       - preview=true  → 浏览器内预览（inline + application/pdf）
       - 越权访问返回 403
```

### 4.3 获取文件详情

```
GET /files/{id}

权限: 文件所有者 / 管理员
返回: File 实体（含 URL 访问路径）
```

### 4.4 查询当前用户文件

```
GET /files/my?bizTypes=user_profile,enrollment

权限: 登录用户
逻辑: - 学员 → 查自己
      - 教练 → 查自己
      - 管理员 → 查自己 + 查他人的走 4.5
```

### 4.5 管理员查询任意用户文件

```
GET /files/user/{userId}?bizTypes=...

权限: 管理员
```

### 4.6 按业务查询附件

```
GET /files/biz/{bizType}/{bizId}

权限: 业务参与方 / 管理员
示例: GET /files/biz/exam_ticket/15
      → 查某条考试报名记录对应的准考证
```

### 4.7 删除文件（逻辑删除）

```
DELETE /files/{id}

权限: 管理员
提示: 仅删除数据库记录，磁盘文件保留
```

## 六、预览实现

### 后端改动

`FileController.download()` 增加 `preview` 参数，切换 Content-Disposition：

```java
@GetMapping("/{id}/download")
public ResponseEntity<Resource> download(
        @PathVariable Integer id,
        @RequestParam(defaultValue = "false") boolean preview) {

    File file = fileService.getById(id);
    // 校验权限...

    ContentDisposition disposition = preview
        ? ContentDisposition.inline().filename(encodedFileName, StandardCharsets.UTF_8).build()
        : ContentDisposition.attachment().filename(encodedFileName, StandardCharsets.UTF_8).build();

    return ResponseEntity.ok()
            .contentType(MediaType.parseMediaType(file.getMimeType()))
            .header(HttpHeaders.CONTENT_DISPOSITION, disposition.toString())
            .body(resource);
}
```

### 前端消费方式

- **预览** → `<a href="/files/{id}/download?preview=true" target="_blank">` 或 `<iframe>`
- **下载** → `<a href="/files/{id}/download">`
- 图片类直接显示 `<img src="/uploads/...">`（静态资源映射已就绪）

## 七、培训记录表 PDF

### 生成流程

```
学员查询进度 → 学时达标 → 前端显示"生成培训记录表"按钮
                                   ↓
                          学员点击生成按钮
                                   ↓
                      POST /training-record/generate
                                   ↓
                   后端查询 training_record 汇总数据
                   查 student_coach 获取教练名
                   从 config 表读驾校名称
                   填充 PDF 模板 → 存到 upload-files/training_record/
                   写入 file 表 (biz_type=training_record)
                                   ↓
                          返回 File 实体 + URL
                                   ↓
                         前端跳转预览 or 下载
```

### PDF 内容

- 学员姓名、身份证号
- 报考车型、科目
- 累计学时（按科目统计）
- 教练姓名
- 驾校名称
- 生成日期

## 八、向后兼容

1. **旧数据** — `biz_type` / `biz_id` 可为 NULL，不影响已有记录
2. **旧接口** — `GET /files/user/{userId}` 保留，转发到新查询逻辑
3. **旧上传** — 不带 `bizType` 时降级为按 `fileType` 处理
4. **旧文件类型** — `file_type` 字段保留不改，新代码优先使用 `biz_type`
